### 3.2 日历

- 月 / 周 / 议程三视图；事件增删改；全天与定时；多个本地日历。
- 重复事件常用子集（DAILY / WEEKLY / MONTHLY / YEARLY，`COUNT` / `UNTIL`），展开在 `me-core` 纯函数里，时区存 UTC + IANA。
- 最多 3 个提醒；应用内 30 秒扫描 + `calendar_reminder_fires` 主键去重。
- 修过一个 P0：范围查询与提醒查询原来用 `start_utc <= to ORDER BY start_utc LIMIT 200`，300 条已结束重复事件会把当月事件挤掉（月视图空白、提醒静默失效）；改为加 `recurrence_until` 冗余列 + 拆「一次性 / 重复未结束」两条查询，已用 SQLite 复现验证。
- **ICS 导入导出未做**，见 §7 P0-4。

### 3.3 天气（和风天气 QWeather）

- 城市搜索（`number=20`，标题到县级市：`地点 · 上级市 · 省`）、多地点列表、默认地点。
- 当前天气 + 24h 折线 + 7 天预报；SQLite 缓存离线可用；快照 payload 带 `v`，版本不符按无缓存处理。
- **按地点刷新**（D38）：单飞 / 60s 最小间隔 / 30s→2m→5m 退避都按地点各自算，新增地点立刻拉它自己。
- 图标全部矢量自绘，未知天气画「?」而不是云（D37）；保留原始图标码区分昼夜。
- 配置弹窗定版（2026-11-06）：三步说明 → `API HOST :` / `API KEY :` 两行对齐 → `[保存][测试连接][取消]` + 右侧「当前状态」；Key 暗文，已保存用 `••••••••` 占位。
- **Key 与 Host 一起存 `meta`**（2026-11-06，取代 keyring）：根治「重配才生效、退出就失效」。

## 4. 架构落地要点

| 规则 | 落地情况 |
| --- | --- |
| 依赖方向 `me-app → me-sync → me-core/me-store/me-proto` | 保持；`me-core` 无 tokio/rusqlite/reqwest |
| **用例下沉、双入口**（§2.7）：UI 与 AI 工具走同一用例函数 | 已做：天气 `weather_candidates/snapshot/locations`、日历 `calendar_*`、音乐经 `Event`+`Command` 回执桥接 |
| `Command` / `Event` 只做加法 | 已做；新增 `Event::is_progress` 覆盖 `AiStreamDelta`，避免进度事件被当关键事件背压 |
| 破坏性操作不直连 | `calendar_delete` 只发确认，执行交给用户点击；音乐执行在 `me-app` |
| 安全边界 | 天气 Host 必须公网 https（按字面量拒内网）；AI 输出按 Markdown 子集渲染，不执行 HTML、不加载图片 |
| 密钥 | 账号密码/OAuth 仍走 keyring；**AI 与天气 Key 明文存 `meta`**（用户明确要求，代价见 §5） |

## 5. 关键决策与偏差（评审时要看的几处）

**已定决策**（完整 25 条见架构文档 §9.1，此处只列影响面最大的）：

- D16 不新增 crate，`me-sync` 扩为后端服务门面；D17 日历本地优先、不做 CalDAV；
- D19 提醒只在应用运行时触发；D20 天气用和风、Host 可配；D22 工具白名单最小化；
- D26 四个功能各有 `meta.feature_*` 开关 —— **实际未接线**，见 §7 P1-8；
- D33 AI 写日程直接生效、靠 `source=ai` + 撤销 + 限额兜底；
- D37 天气图标矢量自绘且必须逐类可区分；D38 刷新按地点；D39 标题显示到县级市；D40 横向行宽度交给 egui 布局（防面板正反馈变宽）。

**实现期偏差 7 条**（全部写进架构文档「实现状态」段，评审逐条确认）：

1. `AiStreamDelta` 不做累积全文合并（通道撑不住），终止后从库重载；
2. `Selection` 选区引用未启用（HTML 自绘 `LayoutJob` 取不到选区），v0.3 只做整封引用；
3. 模型返回白名单外工具名按**协议错误**处理，而不是回一条 `is_error` 工具结果；
4. 单份 `ai_config` 改为**模型档案列表**（`ai_models` + `ai_active_model`，v4 加列）；
5. **AI Key 改为档案普通字段**（明文进 `meta.ai_models`），不再走 keyring；
6. AI 设置改为独立 `Modal`，「新建模型」只列 5 项；
7. **天气 Key 与 Host 一起存 `meta.weather_api_key`**，不再走 keyring。

**两处安全代价（不是疏漏，必须知道）**：`myemail.db` 里能直接读到 AI Key 与天气 Key，失去了 DPAPI 加密保护。补偿手段只有三条——`Debug` 脱敏、进不了日志/事件、界面暗文；发布说明与 README 都要如实写。
