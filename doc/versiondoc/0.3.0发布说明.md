# MyEmail 0.3.0 发布说明

> 本次是 v0.3 的完整交付：在 v0.2 邮件主链路上新增**日历 / 天气 / AI 对话 / 音乐播放器**四个页面，
> 数据库从 schema 2 一路升到 **schema 5**。邮件收发、检索、草稿、HTML 渲染的行为保持不变。
>
> 交付物在 `dist/0.3.0/`：`myemail.exe`、`0.3.0code.zip`（与 exe 同源的源码）、本说明。
> `dist/v03/`（schema 3，无 AI）与 `dist/v04/`（schema 5，AI 首版）是过程快照，**请用 `0.3.0/`**。

## 版本与数据库

| 项 | 值 |
| --- | --- |
| 产品版本 | `0.3.0` |
| 数据库 | `schema_version = 5` |
| 迁移路径 | v1 → v2 → v3 → v4 → v5，启动时自动执行，单事务，失败回滚且版本号不动 |
| v3 | 新增 11 张表（日历 4 / 天气 2 / AI 5），并写入默认日历「我的日历」 |
| v4 | `ai_conversations` 加列 `model_id` |
| v5 | `ai_messages` 加列 `plan` |
| 备份 | v1→v2 生成 `myemail.db.bak-v1`，v2→v3 生成 `myemail.db.bak-v2`；之后只加列，不再备份 |

**降级警告**：v5 数据库不能被 0.2.x 打开（会提示「schema_version 高于本程序支持」）。
要退回旧版，先备份整个数据目录，再删除 `myemail.db*` 让旧版重建——**会丢失本地邮件缓存**，服务器上的邮件不受影响。

## 本次新增

### 日历

- 多个本地日历；**月 / 周 / 议程**三视图；全天与定时事件；事件可编辑、可删除。
- 重复事件常用子集：`DAILY` / `WEEKLY` / `MONTHLY` / `YEARLY`，支持 `COUNT` / `UNTIL`；
  时区存 UTC + IANA，跨时区与跨年展开由 `me-core` 纯函数完成。
- 每个事件最多 3 个提醒；应用运行时每 30 秒扫描，靠 `calendar_reminder_fires` 主键去重，**应用关闭不提醒**。

### 天气（和风天气 QWeather）

- 城市搜索（标题显示到县级市，避免一堆同名候选）、最多 **8 个地点**、默认地点。
- 当前天气 + 24 小时折线 + 7 天预报；快照落 SQLite，**断网也能看缓存**（带版本号，版本不符按无缓存处理）。
- 刷新**按地点**为单位：每个地点各自单飞、60 秒最小间隔、30s→2m→5m 退避，互不拖累。
- 图标全部矢量自绘（晴/多云/阴/雨/雪/雾/霾/沙尘/未知各有特征件，未知画「?」）。
- 配置：页面右上角「配置密钥」，只填 **API Host**（裸域名即可）与 **API Key**（暗文输入），可先「测试连接」
  （发一次真实请求，不落库）。

### AI 对话

- 协议：Anthropic Messages 与 OpenAI 兼容；流式输出、停止生成、重新生成、token 用量展示。
- 多份**模型档案**（名称 / 协议 / 端点 / 模型名 / Key / 工具开关 / 长度预算），每个对话可单独绑定。
- **14 个工具、9 个权限开关**：邮件检索与读正文、天气、日历增改删（删除需确认）、记忆写入、音乐四件套、任务清单。
  关掉的工具既不下发也不执行；每次调用必须给出 `motive`，回复末尾按 `[结果]` 四段呈现。
- 邮件结果以卡片展示命中理由，点开在当前页原地弹出阅读窗；删除日程确认后 10 秒内可撤销。
- 隐私：正文只有用户点「引用到 AI 对话」才进请求；输出按 Markdown 子集渲染，不执行 HTML、不加载图片。

### 音乐

- 选目录递归扫描（深度 ≤8、≤2000 文件、不跟随符号链接），支持 MP3 / FLAC / WAV / OGG。
- 左侧播放列表；主区上为专辑页（封面 + 标签 + 进度 + 上一首/播放暂停/下一首）、下为 48 柱实时频谱。
- 正序 / 随机，切页不中断；不复制、不改写源文件。

### 导航

- 顶部页签：`邮件 / 日历 / 天气 / AI / 音乐 / 账户 / 设置`，`Ctrl+1..7` 直达。
- 邮件页布局与左侧文件夹侧栏保持 v0.2 的样子。

## 升级须知

1. **天气 API Key 需要重新粘贴一次**：0.3.0 起 Key 与 Host 一起存在本机 `meta` 里（不再写系统密钥库），
   旧版存在 keyring 里的值不会被读取。填好点「保存」即可，之后退出重进仍有效。
2. **AI 的 API Key 也存在 `meta` 里**：按用户要求与端点、模型名等参数一起保存。
3. 本地数据库会被自动升级；升级前建议复制一份 `%APPDATA%\MyEmail\` 目录。
4. 首次启动仍会提示「本地缓存为明文保存」。

## 安全与隐私（如实说明，不是疏漏）

- **AI Key 与天气 Key 明文存在 `myemail.db` 的 `meta` 表**，读得到数据库就读得到 Key，
  也不再享受 Windows 凭据管理器的加密保护。补偿手段有三条：不进日志、不进事件载荷、界面只用暗文显示。
- 账号密码与 OAuth 刷新令牌仍走系统密钥库（不可用时仅本次会话记忆）。
- AI 的权限边界固定：只读本地邮件与天气、只创建/修改/删除（需确认）日历事件、只写实体记忆；
  不发信、不碰附件、不做任意 URL/SQL/Shell 调用。
- 天气 Host 必须是公网 HTTPS（按字面量拒绝本机/内网地址）；AI 与天气请求都禁重定向、限响应大小。

## 已知限制

- HTML 渲染器 v2 是邮件排版子集：不执行 JS、不加载外部 CSS/字体、不用 WebView；
  `position`/`float`/`flex`/`grid` 按块级文档流降级；复杂阴影与渐变不还原。
- 密送地址只存本地 `drafts.bcc_addrs`，不写入 RFC 5322 原文。
- 服务器无 `UIDPLUS` 时，旧草稿版本会留 `\Deleted` 副本并提示。
- 应用关闭后：不同步、不提醒、不播音乐。
