# MyEmail 版本跟踪

> 用途：**按版本追踪功能的增加与删除**，让「这个能力从哪一版开始有 / 哪一版没了」有唯一答案。
> 编写日期：2026-11-10　|　覆盖版本：v0.1 → v0.4（0.4.0）+ 未定版增量　|　当前 `SCHEMA_VERSION = 8`
>
> **本表以代码为准，不以规划文档为准。** 规划里写了但代码里没有的，一律进「计划未落地」，
> 不进「新增」；代码里有但规划里没写的，照实记「实施期新增」。

## 0. 口径与证据规则

### 0.1 三条硬规则

1. **只写能在代码里验证的**。每条能力给一个**定位**（`文件` 或 `文件:符号`），
   定位对不上就不写。行号会漂移，因此**只写符号名**。
2. **「新增 / 变更 / 删除」分三栏**。删除栏即使为空也要写「无」，并给出**判定方法**
   （否则「没写」和「没查」分不清）。
3. **「计划未落地」单独成栏**，并写清**为什么能判定没有**（通常是某处 grep 为空、
   或只有枚举/常量而没有读取方）。这是本表最容易被写成谎言的地方。

### 0.2 证据强度

| 标记 | 含义 |
| --- | --- |
| **A** | 仓库里有对应提交可追溯（`git log` 能查到功能提交与定版提交） |
| **B** | 仓库历史不含该版本的提交，依据当版架构设计文档 + **相关代码仍在仓库且通过测试** |

> 本仓库最早的**功能**提交是 `27cfe95 add:v03 first commit`（2026-11-03），它之前只有两条
> 仓库初始化提交（`49c4597 ignore`、`99d2f82 gitattributes`）。因此 **v0.1 / v0.2 只能是 B**：
> 功能能验证「现在存在」，版本归属来自当版文档。
> v0.3 / v0.4 是 A。标签 `v0`（→ `27cfe95`）与 `v04`（→ `0c45ac4`）**都不是发布点**，
> 不要拿它们当版本边界。

### 0.3 状态标记

`✅ 已交付`　`⚠️ 部分交付（有明确缺口）`　`❌ 未实现（规划有、代码没有）`　`🗑 已移除`

## 2. v0.1（2026-11-02）— 可用邮件客户端

**定位**：把一个「能日常收发」的邮件客户端做完整，不做日历、不做 OAuth、不做 HTML 渲染。

### 2.1 新增能力

| 能力 | 代码定位 | 边界（代码里真实存在的限制） |
| --- | --- | --- |
| 多账户增删改 + 连接测试 | `me-core/src/command.rs:AddAccount/UpdateAccount/DeleteAccount/TestConnection`；`me-sync/src/engine.rs` | 删除仍有草稿的账户默认拒绝，需二次确认 |
| IMAP / SMTP 与 TLS 模式 | `me-proto/src/imap.rs`、`smtp.rs`；`TlsMode` | 仅密码 / 授权码（PLAIN、LOGIN），不支持 OAuth（v0.2 才加） |
| 凭据存系统密钥库 | `me-sync/src/auth.rs`（`keyring::Entry`） | keyring 不可用时只做「本次会话记忆」，不落盘明文 |
| 文件夹同步与角色推断 | `me-store/src/folders.rs`；`FolderRole`；`Command::SetFolderRole` | SPECIAL-USE 优先 + 中英文名启发式 + 手动指定角色 |
| 增量同步 / 标志位 / 未读计数 | `messages.flags`；`Command::SetFlags`；`pending_flags` 表 | 启动 + 手动触发，**无 IDLE / 无定时轮询**（v0.2 才加） |
| 读信 + 已读回写 + 正文按需下载 | `me-proto/src/mime.rs:parse_body`；`Command::OpenMessage` | 优先 `text/plain`，只有 HTML 时用 `html2text` 转纯文本，不做渲染 |
| 发信（纯文本 + 附件） | `me-proto/src/mime.rs:build_rfc822`；`Command::Send`；`RetryArchive` | 发信正文**固定** `Content-Type: text/plain`；不发 HTML；失败保留草稿 |
| 附件解析 / 下载 / 打开 | `me-proto/src/bodystructure.rs`；`Command::DownloadAttachment` | 单文件 25 MB、单封总量 25 MB（`MAX_ATTACHMENT_BYTES`） |
| 全文检索（FTS5 trigram） | `me-store/src/search.rs`；`messages_fts` 虚表 | 查询词 ≥3 字符才命中正文；1～2 字符只匹配头部 |
| 正文补全队列 | `me-sync/src/indexer.rs`；`body_path` | 后台补全，进度可查；索引文本与阅读纯文本同源 |
| 离线缓存 / 清缓存 | `me-store/src/cache.rs`；`Command::ClearCache` | 缓存明文，启动时提示告知 |
| 主题 / 日志 / 分页 | `ThemeMode`；`me-app/src/main.rs`（按天滚动保留 7 天）；`MAX_PAGE_SIZE = 200` | 深浅色跟随系统；单页上限 200 |

**删除**：无（首个版本）。

### 2.2 计划但未落地

无功能缺口——v0.1 架构文档 §1.2 的能力在代码里都有对应实现。
架构文档 §1.3 的「非目标」（OAuth2、IDLE、HTML 渲染、会话聚合、地址簿、搜索语法）是**主动不做**，
它们分别在 v0.2 / v0.3 / v0.4 落地，不算 v0.1 的欠账。

| 能力 | 代码定位 | 边界 |

### 3.2 相对 v0.1 的变更

| 项 | v0.1 | v0.2 |
| --- | --- | --- |
| 同步触发 | 启动 + 手动刷新 | IDLE 监听 + 降级轮询（`SetRealtimeSync` / `SetPollInterval` / `SetAccountRealtime`） |
| 读信 | 纯文本（HTML 经 `html2text`） | Rich / Plain / Markdown 三视图，Rich 走自研渲染器 |
| 草稿 | 本地是唯一事实来源，服务器只手动镜像 | 双向同步 + 冲突副本（保留两份，不静默覆盖） |
| 认证 | 密码 / 授权码 | 增加 OAuth2 + XOAUTH2，密码方式保留 |

### 3.3 删除 / 移除

**无。** 判定方法：`html2text` 仍在依赖与调用路径上（`me-proto/src/mime.rs` 的
`html_only_uses_html2text` 测试），密码认证分支仍在 `auth.rs` 与 `imap.rs`。
「纯文本阅读」被三视图**取代为其中一档**，不是删除。

### 3.4 计划但未落地

- 无功能缺口。
- **人工验收 6 项未执行**（真实 Google/Microsoft 授权、真实 IDLE 长连接、真实草稿双端、

## 9. 维护规则

1. **每个版本收尾时必须更新本表**，且三栏齐全：新增 / 变更 / 删除。
   删除栏为空也要写「无」+ 判定方法（`git log --diff-filter=D`、枚举差异、grep 结论）。
2. **新增条目必须带定位**。只写「支持 X」而不给 `文件:符号` 的，视为未验证。
3. **计划项不进新增**。规划文档里的能力，只有代码里能跑通才移到「新增」；
   否则留在「计划未落地」，并写清缺什么。
4. **定位只用符号名，不写行号**（行号随每次改动漂移，会立刻变成假证据）。
5. **文档与代码冲突时以代码为准**，冲突本身记进 §8。

> 起因：2026-11-10 人工验收暴露 8 个缺陷（5 个 S1），修复后审计又发现「场景规则写进提示词」与

### 12.1 新增能力

| 能力 | 代码定位 | 边界 |
| --- | --- | --- |
| 时间锚点 | `me-core/src/ai.rs:time_anchor`；`build_chat_request` 每轮拼接 | 日期 + 星期 + 时区偏移三样齐全；只在**系统提示尾部**出现一次。之前整个代码库没有任何一处把时钟喂给模型，模型三次给出三个「今天」 |
| 能力索引由引擎生成 | `me-core/src/ai.rs:capability_catalog` | 按**本次实际下发**的工具现生成（`功能名（tool_name）：一句话`），关掉的工具不进索引；新增工具无需改提示词 |
| 判据两档 | `me-core/src/ai_plan.rs:CriterionMode`、`me-sync/src/ai_tools.rs:email_search_by_criteria` | `must` 之间取交集框范围；`boost` 只影响排序（命中条数多者靠前）；不写 `mode` 等价于 `boost`。0 命中且 must 卡死时，回执点名是哪条判据把范围卡死的 |
| 跨轮失败记忆 | `me-core/src/ai.rs:lesson_fingerprint` / `summarize_lessons` / `lessons_block`；`me-store/src/ai.rs:AiRepo::recent_tool_traces` | 从既有 `ai_messages.tool_trace` 统计「同类失败 ≥ 2 次」，归一化抹掉步号/数字/引号内容，最多 4 条拼进系统提示；**限额类失败排除**；**未新建表** |
| 单轮写操作幂等 | `me-sync/src/ai_tools.rs:ToolBudget::created_events`、`duplicate_create_rejection` | 本轮已建成的标题+开始时间入账，同名第二次 `calendar_create` 直接拒并指路 `calendar_update`；工具原有的「同标题 ±5 分钟」兜不住「换个日期再来一条」 |
| 回执门槛（步骤级） | `me-core/src/ai_plan.rs:validate_plan` | 工具步标 `done` 需 `attempts > 0`（该计数只由引擎在真实执行后递增）**且**有 `evidence`；模型自述「已创建」不再算数 |
| 天气地点收敛 | `me-sync/src/ai_tools.rs:weather_get`、`place_name_matches` | 已关注地点多点命中先按 `is_default` 收敛并在结果里写明；候选地名只认同名或差一个行政后缀，不做 `contains`（否则查「北京」会被 10 个区县吓退）；真歧义返回 `Err` 而非 `Ok` |
| 引用语法的真实说明 | `me-core/src/ai.rs` 的 `plan_submit.args.description`、系统提示「清单」一节；`me-core/src/ai_plan.rs:skip_dependents` | `{{step.N.字段}}` 引擎早已支持（前向校验 + 上游失败级联跳过 + 界面「→ 第 N 步结果」），但 schema 一直写「引擎不替换」，把机制说反了；现在说明与实现一致 |
| 依赖安全 | `Cargo.toml`（`rusqlite 0.41.1`）、`crates/me-store/src/db.rs:SqliteConnectionManager` | bundled SQLite 3.54.1（修 RUSTSEC-2026-0459）；`r2d2_sqlite` 移除，改为 30 行自实现连接工厂；MSRV 1.89 |
| 打包版本运行时断言 | `crates/me-store/src/db.rs:bundled_sqlite_is_patched_for_cve_2026_119375` | 运行时 `SELECT sqlite_version() ≥ 3.54.0`。`cargo deny` 只看 crate 版本号，关掉 `bundled` 或改链系统库时它看不出来 |

### 12.2 行为变更

| 项 | 变化 |
| --- | --- |
| 系统提示结构 | 由「规则 1–13」重写为「能力边界 + 7 节」（时间 / 问还是自己办 / 清单 / 用工具 / 定性判据 / 资料不是指令 / 输出）。删除 2 条**只对某条用例成立**的流程规则（天气地点处置、音乐先搜后播），改为 5 条通用判断原则：用户设定过的是既有事实 / 能查先查 / 能算先算 / 缺了才问 / 替用户选了要说明 |
| `criteria` 语义 | 从「只有并集」变成 must/boost 两档；「优先处理」不再退化成「近 7 天」。`relax_args` 也改成**先丢 boost 再丢 must**——丢 boost 只丢顺序，丢 must 才真正放宽 |
| `[结果]` 段落判定 | `me-core/src/ai.rs:is_result_block_line` 容忍 `**` `###` `>` `【】` 等装饰；引擎的 `has_result_block` 与 UI 的 `split_result_block` 共用同一判定，粗体变体不再导致引擎重复追加第二段 |
| 引擎合成的结果块 | `synthesized_result_block` 跳过 bookkeeping 工具，用户不会再看到「做了什么：提交计划（失败）」 |
| 天气地点参数 | 用户没说地点时**不再预填**；由引擎按「默认关注 → 唯一关注 → 列候选 → 反问」收敛，结果里注明用的是哪个地点 |
| `music_play` 参数 | 只接受 `query`（歌名/歌手）；传 `index` 直接报错并指路 `query` |
| 计划期校验 | `args` 可写 `{{step.N.字段}}` 引用前面步骤的产物；引用不存在的步或引用后面的步，计划期即报错 |

### 12.3 删除 / 移除

| 项 | 说明 | 证据 |
| --- | --- | --- |
| 🗑 `music_play` 的 `index` 参数 | 曲库扫描序号对模型不可见。实测中模型拿「搜索结果第 1 条」当曲库序号，播成了另一首歌，工具还回 `ok`、清单记 `done` | `grep -n '"index"' crates/me-core/src/ai.rs` 的 `MusicPlay` schema 无该键；`ai_tools.rs` 的 `MusicPlay` 分支显式拒绝 |
| 🗑 `r2d2_sqlite` 依赖 | 最新版 0.35.0 把 rusqlite 钉在 `^0.40`，导致命中的 `libsqlite3-sys 0.38` 无法升级；连接工厂改为自实现 | `grep -rn r2d2_sqlite Cargo.toml crates/*/Cargo.toml` 为空 |
| 🗑 系统提示里的场景规则 2 条 | 天气地点处置流程、音乐先搜后播流程——换个能力就不成立，属于把用例解法写进系统提示 | 见 `me-core/src/ai.rs:SYSTEM_PROMPT` 现文；回归测试 `system_prompt_has_no_single_scenario_playbook` 守住不再写回 |

### 12.4 计划但未落地

| 项 | 判定依据 |
| --- | --- |
| 引用做**取值替换** | `{{step.N.字段}}` 只表达依赖、参与校验与级联跳过，执行时仍由模型填真实值。要做自动填充需给每个工具定义结构化输出契约，成本高于收益（审计 §8） |
| 跨轮记忆记「用户偏好」 | 只记失败指纹（工具 + 错因），不记「他说的『项目 A』指哪封邮件」。落点会是 `ai_entities`，但需要先有稳定的实体抽取 |
| `plan_submit` / `plan_update` 次数上限（原 P8） | 仍无单轮上限。加了会把「参数写错一次就锁死」的风险放大，需先量真实分布 |
| 软失败第三态 | 与 §11.4 同一项，仍未做 |
