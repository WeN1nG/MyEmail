## 一句话

**本地知识库**：导入文档与邮件，在本机做「关键词 + 语义」的混合检索，
让 AI 能引用你自己的资料回答问题——文档内容不上传。

## 一、知识库

### 1.1 三个来源

| 来源 | 怎么来的 | 怎么清 |
| --- | --- | --- |
| **本地文件** | 知识库页「导入文件…」（md / txt / docx / pdf / pptx） | 详情页删除；原文文件不受影响 |
| **邮件** | **自动入库**，容量窗口默认 200 封（全局总量，不是每账户各 200 封） | 随邮件删除；调小容量即清理 |
| **AI 写入** | AI 调 `kb_add` 写进来的文本（`origin = 'ai'`） | 可按来源筛选后批量清理 |

### 1.2 检索：关键词 + 语义，融合后按文档分散

```
query
 ├─ FTS5 unicode61 ──► top 40   关键词命中
 └─ 本机嵌入 → KNN ──► top 40    语义相近
            ↓
      RRF 融合 → 文档级轮转取 → top 8 → 拼进上下文
```

- **嵌入在本机跑**：`bge-small-zh-v1.5`，512 维，模型是**外置文件**（约 96 MB）。
  首次进入知识库页会弹出引导卡让你确认下载——**不会后台偷偷下**。
  文档内容**不因嵌入而上传**（PDF/PPT 的分析另需单独确认，见 1.4）。
- **向量存在独立的 `kb.sqlite`**：可以整文件删除重建，主库与备份不受影响。
- **不下载模型也能用**：只有关键词检索（FTS），功能不残废。

### 1.3 召回质量有评测集，不是「感觉能用」

`doc/versiondoc/v5检索评测.md`：20 条问答对，覆盖四类
（单文档精确 / 跨文档综合 / 专有名词编号 / 同义改写）。

| 指标 | 实测 | 目标 |
| --- | --- | --- |
| RRF `Hit@8` | **20/20 = 1.00** | ≥ 0.85 |
| KNN only | 20/20 | — |
| FTS only | 19/20 | — |
| RRF ≥ 两路单跑 | 达标 | 达标 |

跑法（需要真实模型）：

```bash
cargo test -p me-sync --test retrieval_eval -- --ignored --nocapture
```

### 1.4 PDF / PPT 的导入：交给模型，两级确认

这类文档无法在本地可靠识别内容。导入时整份文件会发给「当前模型」分析并切成语块，
所以有**两级确认**：

1. **总确认**（首次）：费用、隐私、参考价（约 $0.006/页）都在框里说清楚；
2. **每次预估**：本次几页 / 几批 / 多少 token / 大概多少钱。
   **这个框刻意不提供「不再提示」**——它是每次导入唯一的成本闸门。

模型不支持文档输入时，**导入会明确失败**并提示「请更换多模态模型」，
不会悄悄降级成本地抽取文本（那样得到的结果通常很差，而用户不知道）。

设置页有一行「PDF/PPT 分析提示已确认 · [重新显示提示]」，换模型后可以再看一遍。

### 1.5 AI 侧的六个知识库工具

| 工具 | 权限开关 | 作用 |
| --- | --- | --- |
| `kb_search` | 检索与阅读 | 混合检索，返回带 `[kb:N]` 锚点的语块 |
| `kb_read` | 检索与阅读 | 读某份文档的一段语块 |
| `kb_list` | 检索与阅读 | 列文档（按标题 / 状态筛） |
| `kb_add` | 写入与修改 | 写入一段文本（**只收文本，不收路径**） |
| `kb_update` | 写入与修改 | 改标题 / 停用 |
| `kb_delete` | 发起删除 | **只发请求**，用户点确认才真删 |

- `kb_add` 单次上限 8000 字符，**只接受文本不接受路径**——
  否则模型可以传 `C:\...\id_rsa` 读任意本地文件。
- AI 写进来的东西 `origin = 'ai'`，界面可按来源筛选、批量清理。

### 1.6 引用：回答里的 `[kb:12]` 渲染成「标题 · 第 N 块」

- **只在本轮调过检索工具时校验**：模型引用没检索过的文档，那个锚点会被当成编造处理。
- **落库保留原文**，只在渲染这一层换成 chip；点击跳到知识库详情。

## 二、AI 对话界面三处修正（批 1）

| 项 | 变化 |
| --- | --- |
| **检索到的邮件独立成区** | 不再塞在「工具调用」里；跨多次检索按邮件 id **去重**，保留首次命中的理由 |
| **新建对话后跳到新会话** | 原来停在旧会话上——因为新建返回的 id 被丢了 |
| **默认展开任务清单，折叠思考与工具调用** | 任务清单是这轮对话里信息密度最高的地方；工具区折叠后标题带「· 执行中」 |

区块顺序：**思考 → 清单 → 工具 → 检索到的邮件 → 回答**（由 `render_turn` 一处定义，测试钉住）。

## 三、邮件列表与系统通知（批 2 / 8）

- **邮件列表的文本不可选**：拖拽不会误选一片文字，光标是箭头；**阅读页正文仍可正常复制**。
- **系统通知**（新邮件 / 同步失败 / AI 回复）：
  - **只在后台发**——应用在前台时有应用内提示，不重复打扰；
  - 同类有冷却（新邮件 5 分钟、同步失败 30 分钟），同步 10 个文件夹不会弹 10 条；
  - 设置页「通知」分组可逐类关闭。

顺带修掉了后台收信的一个真问题：IDLE 连上后服务器（QQ 实测）不一定推送，
原来的固定等待等于「后台最多半小时不更新邮件，而且一条日志都没有」。
现在等待上限是 `min(29 分钟, 轮询间隔)`，**最差延迟 = 轮询间隔**（默认 60 秒）。

## 五、已知边界

1. **PDF/PPT 需要多模态模型**。不支持文档输入的模型导入会明确失败——
   宁可失败也不要给一份看不懂的抽取结果。
2. **语义检索是可选的**。不下载嵌入模型就只有关键词检索，
   同义改写类查询会搜不到——这是预期降级，不是故障。
3. **系统通知点击不跳转**。Windows 上 action 回调支持有限，第一版只发不接。
4. **邮件自动入库是全局 200 封**，不是每账户各 200 封。
   某个账户邮件特别多时，它会把别的账户挤出去——界面顶部的「其中 xxx 封」能看到分布。
5. **向量库与模型都是可丢弃物**。删掉 `kb.sqlite` 或 `models/`，
   应用照常启动，知识库退化成「只剩语块的关键词检索」。
