# MyEmail 0.4.0 发布说明

> 本次是 v0.4 的完整交付：邮件主链路加**搜索语法与保存的搜索、批量多选、联系人自动补全、
> 统一收件箱、会话线程**五项能力，数据库从 schema 5 升到 **schema 7**。
> 日历 / 天气 / AI / 音乐四个模块与 v0.3 行为一致，本版未改动它们的接口与权限边界。
>
> 交付物在 `dist/0.4.0/`：`myemail.exe`、`0.4.0code.zip`（与 exe 同源的源码）、本说明。
> `dist/v04/`（schema 5，AI 首版过程快照）与 `dist/v03/`（schema 3）仅作历史留档，**请用 `0.4.0/`**。

## 版本与数据库

| 项 | 值 |
| --- | --- |
| 产品版本 | `0.4.0` |
| 数据库 | `schema_version = 7` |
| 迁移路径 | v1 → v2 → v3 → v4 → v5 → v6 → v7，启动时自动执行，单事务，失败回滚且版本号不动 |
| v6 | 纯索引调整（不动列/约束）：`messages` 的 `folder_date` / `body_pending` 索引补 `id DESC`，新增未读计数表达式索引 |
| v7 | 新增 `contacts`（联系人）与 `saved_searches`（保存的搜索）两张表；`messages` 加 `in_reply_to` / `"references"` 两列 |
| 备份 | v1→v2 生成 `myemail.db.bak-v1`，v2→v3 生成 `myemail.db.bak-v2`；之后只加列/加表，不再自动备份 |

**降级警告**：schema 7 的数据库**不能被 0.3.x 打开**（会提示「schema_version 高于本程序支持」）。
要退回 0.3.x，先备份整个数据目录，再删除 `myemail.db*` 让旧版重建——**会丢失本地邮件缓存与联系人**
（服务器上的邮件不受影响）。

## 本次新增

### 搜索：速记语法 + 条件面板 + 保存的搜索

- 搜索框支持 `from:` `to:` `subject:` `has:attachment` `has:none` `before:` `after:` `is:unread`，
  日期可用 `today` / `yesterday`；值两侧的引号会被剥离。
- 条件面板提供**发件人 / 收件人 / 主题 / 仅未读**四个输入，与速记语法同时存在时**面板优先**。
- 已生效的条件以 chips 展示，可单条删除；拼错的片段（如 `fromm:`）**照常搜索并给一条提示**，不清空输入。
- **保存的搜索**只存条件、不做自动动作：工具栏「保存此搜索」（空条件时禁用），列表可点击执行、可删除；
  名称重复会提示「已经存在了，换个名字吧」，不会静默失败。

### 批量多选

- `Ctrl` 点击切换单封，`Shift` 点击选锚点到达的区间，裸点击清空并打开邮件。
- 批量动作：**标为已读 / 标为未读 / 加星 / 取消加星 / 删除**；删除弹确认卡。
- 切账户、切文件夹、加载新一页、退出搜索、删除消息时集合自动清空，不会跨列表残留。

### 联系人自动补全

- 联系人在**正文补全落库后**（取发件人 / 收件人 / 抄送）与**发信成功后**（取收件人 / 抄送 / 密送，
  不含用户自己）自动累积；只存本地，**永不出网、不进 AI 请求**。
- 撰写页三个地址框都有下拉候选；前缀取**正在输入的那一段**，选中后替换该段、不动前面的地址。
- 前缀不足 2 个**字节**不查库（单个汉字是 3 字节，仍会查——一个姓氏就有意义）；查库失败静默降级为空候选。

### 统一收件箱

- 侧栏「统一收件箱」虚拟项：各账户 `role=inbox` 文件夹的并集，列表多一列「账户」，带跨账户未读合计。
- 与文件夹选择互斥；切换时清空列表与多选集合。
- 聚合模式下搜索**不限账户**；批量删除按**每封邮件所属账户**分别进各自废件箱。

### 会话线程

- 列表按 `References` 根折叠成一行，显示 `▸ N`；展开显示 `▾ N`，组内按时间正序、后续行带 `↳` 缩进。
- 工具栏「线程」开关可关掉折叠（关掉即一封一行，便于排查「以为丢邮件」）。
- 线程 ID 带账户，**跨账户不合并**；缺 `Message-ID` 的邮件退化成独立线程，不会挤成假线程。

## 实现要点（与使用者相关的部分）

- **统一收件箱的聚合在存储层一次查完**，不是 UI 逐账户拉再合并——后者会破坏键集分页，
  也会让「加载更多」在跨账户时重复或跳行。
- **线程头的补全是离线任务**：读本地 `raw/*.eml.gz` → 解析 → 写回两列，**不联网**、不占 IMAP 连接预算；
  启动时自动跑一次（手动重跑目前只有命令层入口，界面未接）。只处理本地已有原始报文的邮件。
- **`NULL` 与 `"[]"` 在 `"references"` 列语义不同**：`NULL` = 还没回填过，`"[]"` = 回填过但确实没有引用链。
  回填队列靠这个区分，避免没有回复头的邮件每次启动被重解析。
- 联系人累积是**批量 UPSERT**，且放在正文落库**之后**、失败不报错——不让附带功能拖慢「正文能搜到」的主线。

## 升级须知

1. 数据库会被自动升级到 schema 7；升级前建议复制一份 `%APPDATA%\MyEmail\` 目录。
2. **联系人表从空开始**：历史邮件不会自动补录联系人，只有之后补全过正文 / 发出的邮件才会累积。
3. **历史邮件的线程需要一次回填补齐**：启动时会自动跑，进度取决于本地 `raw/` 的邮件数量；
   没打开过（因此没有本地原始报文）的历史邮件仍会单独成串。
4. 天气 API Key、AI Key 的存放方式与 0.3.0 相同（本机 `meta` 表），**升级不需要重新填写**。
5. 首次启动仍会提示「本地缓存为明文保存」。

## 安全与隐私（如实说明）

- 联系人、保存的搜索都是**纯本地数据**；联系人不参与 AI 请求，也不随任何网络请求发出。
- 账号密码与 OAuth 刷新令牌仍走系统密钥库；AI Key / 天气 Key 仍明文存在 `meta` 表
  （不进日志、不进事件载荷、界面只用暗文显示）。
- AI 权限边界未变：只读本地邮件与天气、只增删改日历（删除需确认）、只写实体记忆；
  不发信、不碰附件、不做任意 URL/SQL/Shell 调用。
- 批量删除仍是**破坏性操作前的确认 + 服务端 UIDPLUS 能力检查**；不支持 UIDPLUS 时不执行永久删除。

## 已知限制

- 统一收件箱里新到达的邮件**不增量插入**，要等下一次刷新（列表其它模式正常增量）。
- HTML 渲染器仍是邮件排版子集：不执行 JS、不加载外部 CSS/字体、不用 WebView。
- 密送地址只存本地 `drafts.bcc_addrs`，不写入 RFC 5322 原文。
- 服务器无 `UIDPLUS` 时，旧草稿版本会留 `\Deleted` 副本并提示。
- 应用关闭后：不同步、不提醒、不播音乐。
- 搜索语法不支持 `OR`、括号与引号短语（引号只做剥离）。
